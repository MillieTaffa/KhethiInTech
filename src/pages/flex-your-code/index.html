Your first hackathon

A small plan beats a big idea

1. Find a teammate

Use the event’s official discussion space. Say what you can do, what you want to learn and how much time you have.

2. Choose a tiny project

Pick one user and one problem. Build one complete path that works; a small finished prototype is easier to explain.

3. Prepare the repo

Create a public Git repository, add a short README, list setup steps, credit external libraries and do not commit API keys or personal data.

4. Submit early

Check the event timezone, required video, demo link, repository access, screenshots and team details. Reopen your submission to confirm it saved.

Project pitch template

Problem: Who struggles, and with what?

Solution: What does your project let them do?

Demo: Show one complete user journey.

Build: Which tools did you use, and what did each teammate contribute?

Next: What would you improve after the event?

Judging and portfolio checklist

  • Explain the user problem and why it matters.
  • Show a working feature rather than only slides.
  • Make the README and demo easy to follow.
  • Credit libraries, datasets, AI tools and prior work.
  • Add your role, decisions, challenges and lessons to your portfolio after the event.
  • Participation builds skills even without a prize; prize money is never guaranteed income.

How KIT checks free entry

We review official event pages and rules for dates, fees, eligibility, format and required tools, plus the discovery platform’s participant terms. If a mandatory cost is unclear, the event stays off the active list. Check API limits before building.
