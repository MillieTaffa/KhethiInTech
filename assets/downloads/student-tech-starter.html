01 · Pick a direction

Choose the work, not the fanciest title

Tech is a collection of jobs. You can change direction as you discover what you enjoy. These are starting points, not boxes you must stay inside.

Build software

Make websites, applications and tools.

Try: HTML, CSS, JavaScript or Python, Git and testing.

Work with data

Find useful answers in information.

Try: spreadsheets, SQL, Python, charts and data cleaning.

Protect systems

Help people and organisations reduce security risk.

Try: networking, Linux, safe labs and clear security notes.

Make systems run

Deploy and maintain services and infrastructure.

Try: Linux, networking, scripting, containers and cloud basics.

Ask yourself

  • Would I rather create a screen, investigate a pattern, solve a security puzzle or keep a service reliable?
  • Which school subject, hobby or everyday problem makes me curious?
  • What can I try for two weeks before I decide whether I like it?
Try this: choose one role to explore for a month. You are testing an interest, not signing a lifelong contract.

Explore local training options through WeThinkCode_ at https://wethinkcode.co.za/ and South African youth openings at https://sayouth.mobi/. Confirm current requirements and dates on each official site.

02 · A free-first learning plan

Make progress in twelve weeks

Aim for three to five focused hours a week. If exams or life get busy, keep one small weekly session. Consistency beats a heroic weekend followed by a three-month disappearance.

Weeks 1 to 2
Choose one learning path. Set up a folder, create a GitHub account if you can, and learn basic file and terminal navigation.
Weeks 3 to 4
Learn core concepts. Follow one beginner course. Take notes in your own words. Do the exercises yourself before peeking at solutions.
Weeks 5 to 6
Build a tiny project. Pick a problem you care about. Make the first version small enough to finish in a week.
Weeks 7 to 8
Improve it. Add one feature, tests or accessibility improvements. Ask a classmate, mentor or teacher to try it.
Weeks 9 to 10
Explain the work. Write a README with the goal, setup, features, tools and lessons learned. Add screenshots only if they help.
Weeks 11 to 12
Show it and choose again. Share the project, update your CV and decide whether to continue this path or explore another.

03 · Build something real

One small project can teach a lot

A project does not need artificial intelligence, blockchain and a launch party. It needs a clear purpose and a finished first version.

Web developer

Make a mobile-friendly page for a club, student society or local service. Add accessible navigation and a contact route.

Data learner

Use a public dataset to answer one question. Explain how you cleaned it and show a simple chart with a useful caption.

Security learner

Write a checklist for account safety or explain a finding from an intentionally vulnerable practice lab. Test only with permission.

Cloud learner

Publish a static page, write down the steps, set a budget alert if a cloud account is involved and remove resources when done.

Your project README

  1. Purpose: Who is this for, and what can they do?
  2. Build: What works, which tools did you use, and how can someone try it?
  3. Learning: What surprised you, and what are the limits?
  4. Next: What would you improve with more time?
Portfolio rule: label team work honestly. Say what you made, what someone else made and which parts you can explain.

Before you publish

  • No passwords, access tokens or private keys in the repository
  • No private student data in screenshots or sample files
  • Every external source is credited or linked
  • The project opens on a phone and with a keyboard

04 · Make opportunities easier to reach

A simple student application kit

You do not have to apply everywhere. Keep a small record, check the official requirements and make each application clear.

One-page student CV outline

Name and contact: professional email, location and portfolio link.

Short profile: what you are learning, the kind of opportunity you want and one strength you can support with evidence.

Education: school or programme, dates and relevant subjects or modules.

Projects: two or three examples with your contribution, tools and a link.

Skills: list tools you have actually used. Mark coursework or learning in progress clearly.

Experience: include school, volunteering, family or community responsibilities when they show relevant skills. Do not invent work experience.

Weekly opportunity routine

  1. Choose one afternoon to check a school, academy, bursary or internship source.
  2. Save the organisation, official link, deadline, requirements and next action.
  3. Ask a trusted person to review important applications.
  4. Keep copies of your CV and project links in one folder.
  5. Follow up politely if the organisation says that is welcome.
Pause if: someone asks you to pay a surprise recruitment fee, share a password or send sensitive documents through an unverified account. Find the official contact details yourself and confirm the request.

South African student funding information: https://www.nsfas.org.za/. Current youth opportunities: https://sayouth.mobi/. These are starting points; read each active programme's eligibility rules.
